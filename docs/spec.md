# 統合入退室・環境監視システム 仕様書 (Rust Windows GUI)

> PO 提示の仕様書 (2026-11-17)。原文のまま保存し、変更は PO の指示があった場合のみ行う。
> 実装上の解釈・前提・フェーズ分けは [requirements.md](requirements.md) に記載する。

## 1. システム概要
Windowsベースの入退室管理、環境監視、鍵管理、電源監視を統合した監視・制御ソフトウェア。
- **規模要件**: 最大20万人分のユーザーデータ、最大5,000個の監視・制御オブジェクト（リーダー、ドア、センサー、PDU等）を遅延なく管理・描画可能であること。
- **スケーラビリティ**: 小規模構成（カードリーダー単体）から大規模構成（耐故障ゲートコントローラ・環境監視・鍵管理・PDU連携）まで、設定とライセンス/構成ファイルで柔軟に対応。

## 2. 対応ハードウェア・機能モデル（論理インターフェース定義）
実機プロトコルは抽象化トレイト（Trait）として実装し、モック（シミュレータ）での完全な自動テストを可能にすること。

1. **必須構成（基本入退室）**
   - **カードリーダー**（SS2269VHC-Lite / SS2279VHC-RS-FS 相当）: カードID・認証電文の受信、LED/ブザー制御指令。
   - **電気錠・ドアセンサー**: 解錠指令の出力、施錠/解錠状態および扉開閉状態の接点監視。
2. **オプション構成（システム構成定義により有効化）**
   - **耐故障ゲートコントローラ**（PS-XGCUBE 相当）: 上位PC通信断時のスタンドアロン認証・アンチパスバック制御・履歴バッファリング。
   - **鍵保管器**（SS2280BL-E 相当）: 物理鍵の持ち出し・返却監視、入室履歴との連動（入室記録がないユーザーの鍵取り出し禁止）。
   - **環境監視ユニット**（DT-M01 / ND-EW04E / ND-IOTR / ND-SW01 / ND-SW02DI 相当）: 温度・湿度・電圧・電流のアナログ値監視、接点入力（DI）監視、接点出力（DO）制御。
   - **インテリジェントPDU**（Geist PDU 相当）: ラック内コンセントバーの電力監視・アウトレット単位の電源制御。

## 3. コア制御・監視ロジック要件
1. **認証・解錠フロー**:
   - カードリーダーからの電文を解析し、ローカルDB（最大20万ユーザー）の権限・スケジュールと照合。
   - 許可された場合、対象電気錠へ解錠指令を送信し、履歴をDBに記録。
2. **連動制御（インターロック）**:
   - ルールエンジンを搭載し、「特定エリアへの入室履歴がある場合のみ、対象ラックの扉解錠や鍵保管器の解錠を許可する」等の条件付き連動制御を実行可能とすること。
3. **ドアこじ開け・開放放置アラーム（重要）**:
   - ドアセンサーで「開」状態を検知後、設定された閾値時間（例: 10秒）以上継続した場合：
     - PCから警告音（アラーム音声）を再生する。
     - GUIマップ上の該当ドアアイコンを**赤色で点滅**させ、アラーム一覧に警告を表示する。
     - ドアが「閉」に戻るか、オペレーターが確認操作を行うまで状態を維持する。
4. **状態表示**:
   - 電気錠の「施錠 / 解錠 / 異常」およびドアの「閉 / 開 / 開放放置警告」をリアルタイムでGUI上に視覚表示する。

## 4. 監視画面・カスタマイズ要件（ビルダー機能内蔵）
顧客ごとに異なるフロア図やラック配置に対応するため、**同一の実行バイナリ**で以下を実現する。
1. **モード切替**: 「監視運用モード」と「監視画面作成（レイアウト編集）モード」を内蔵する。
2. **下絵（背景マップ）読み込み**: PNG / JPEG / SVG 等のフロア図面を下絵として読み込み、ズーム・パン・階層（フロア/エリア）切替ができること。
3. **スクリプト・設定駆動のオブジェクト配置**:
   - 画面レイアウトとオブジェクトの振る舞いは、外部ファイル（JSON/TOML + Rhai または Lua 等の軽量組み込みスクリプト）として保存・読み込み可能とする。
   - 編集モードで下絵上にアイコン（ドア、リーダー、温湿度計、PDU等）をドラッグ＆ドロップ配置し、通信IDや連動スクリプトを紐づけて保存できること。

## 5. ネットワーク・セキュリティ・外部連携要件
1. **通信プロトコルと暗号化**:
   - 監視ネットワークは Ethernet / IP ベースとする。
   - 端末・コントローラ間、および外部連携のすべての通信において**暗号化（TLS 1.3 または AES-256-GCM による電文暗号化・認証）を必須**とする。平文通信は設定で明示的にデバッグ許可しない限り拒否する。
2. **上位クラウド・WebAPI連携**:
   - REST API（HTTPS）または gRPC サーバー/クライアント機能を搭載し、他社クラウドサービスからのユーザー情報同期、遠隔解錠指令、履歴・センサーデータ取得が可能であること。
   - 権限ベースアクセス制御（RBAC）により、ログイン権限に応じた操作制限を行うこと。

## 6. 非機能・テスト要件
- **パフォーマンス**: 20万ユーザー検索が10ms以内、5,000オブジェクトの状態更新・描画が30fps以上で動作すること。
- **テスト容易性**: すべてのハードウェア通信はシミュレータ（仮想デバイス）と接続して結合テストができること。
