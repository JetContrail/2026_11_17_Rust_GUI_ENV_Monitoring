# 要求仕様 v1.0 (実装上の解釈・前提・フェーズ)

ステータス: **PO 承認済み** (2026-11-17、§5 の決定事項)

正となる仕様は PO 提示の [spec.md](spec.md)。本書は spec.md の各項目に要件 ID を振り、実装上の前提とフェーズ分けを記載する。
機能イメージは中央電子 [Acsaran-DX](https://www.cec.co.jp/product/security/acsaran-dx)。

## 1. 要件 ID

| ID | spec.md | 要件 |
|----|---------|------|
| SYS-1 | §1 | ユーザ 20 万人、オブジェクト 5,000 個を遅延なく管理・描画 |
| SYS-2 | §1 | 小規模〜大規模を設定とライセンス / 構成ファイルで切り替える |
| HW-1 | §2 | 実機プロトコルは抽象トレイトで実装し、シミュレータで完全な自動テストを可能にする |
| HW-2 | §2.1 | カードリーダ: カード ID・認証電文の受信、LED / ブザー制御指令 |
| HW-3 | §2.1 | 電気錠・ドアセンサ: 解錠指令、施錠 / 解錠状態と扉開閉状態の接点監視 |
| HW-4 | §2.2 | ゲートコントローラ (任意): 上位通信断時のスタンドアロン認証、アンチパスバック、履歴バッファリング |
| HW-5 | §2.2 | 鍵保管器 (任意): 持出・返却監視、入室履歴との連動 (入室記録がないユーザの鍵取出し禁止) |
| HW-6 | §2.2 | 環境監視ユニット (任意): 温度・湿度・電圧・電流のアナログ監視、DI 監視、DO 制御 |
| HW-7 | §2.2 | PDU (任意): 電力監視、アウトレット単位の電源制御 |
| AC-1 | §3.1 | カード電文をローカル DB (20 万ユーザ) の権限・スケジュールと照合し、許可なら解錠指令を送って履歴を記録 |
| IL-1 | §3.2 | ルールエンジンによる条件付き連動制御 (入室履歴を条件にラック扉・鍵保管器の解錠を許可など) |
| AL-1 | §3.3 | ドア開が閾値時間 (例 10 秒) 以上続いたら、警告音・ドアアイコン赤点滅・アラーム一覧表示。閉に戻るか確認操作まで維持 |
| ST-1 | §3.4 | 電気錠「施錠 / 解錠 / 異常」、ドア「閉 / 開 / 開放放置警告」をリアルタイム表示 |
| UI-1 | §4.1 | 同一バイナリに監視運用モードと監視画面作成モードを内蔵 |
| UI-2 | §4.2 | 下絵 GIF / JPEG の読込、ズーム・パン、階層 (フロア / エリア) 切替 |
| UI-3 | §4.3 | レイアウトと振る舞いを外部ファイル (JSON/TOML + Lua) で保存・読込 |
| UI-4 | §4.3 | 編集モードでアイコンをドラッグ & ドロップ配置し、通信 ID・連動スクリプトを紐付けて保存 |
| UI-5 | §4.4 | 監視運用時の操作 (状態確認・遠隔解錠・アラーム確認など) は下絵上のオブジェクトに対して行う |
| NW-1 | §5.1 | Ethernet / IP。全通信を暗号化 (TLS 1.3 または AES-256-GCM)、平文は明示的なデバッグ許可時のみ |
| API-1 | §5.2 | REST (HTTPS) または gRPC: ユーザ同期、遠隔解錠、履歴・センサデータ取得 |
| API-2 | §5.2 | RBAC によるログイン権限ごとの操作制限 |
| PF-1 | §6 | 20 万ユーザ検索 10 ms 以内 |
| PF-2 | §6 | 5,000 オブジェクトの状態更新・描画 30 fps 以上 |
| TS-1 | §6 | 全ハードウェア通信をシミュレータと結合テストできる |

## 2. 前提 (spec.md で決まっていない点の仮定)

| # | 前提 |
|---|------|
| A1 | 実機の電文仕様は公開資料にないため、機器ごとに `DeviceAdapter` 実装を差し替える。最初は自前の電文仕様とシミュレータで実装し、実機アダプタは仕様入手後に追加する |
| A2 | 開放放置の閾値は既定 10 秒で、扉ごとに変更できる |
| A3 | こじ開け (解錠指令なしでドアが開く) は閾値を待たずに即時、開放放置と同じ表示で警報する |
| A4 | 解錠指令後、既定 5 秒で自動施錠する (扉ごとに変更可)。この間にドアが開いても警報しない |
| A5 | アラームは確認・復旧後もアラーム一覧と履歴に残る (発生・確認・復旧の時刻を記録) |
| A6 | データ保存は SQLite (アプリに同梱、追加インストール不要)。照合はメモリ上の索引で行い PF-1 を満たす |
| A7 | 画面レイアウトは JSON (エディタが保存)、システム構成 (有効にする機器・オプション) は TOML |
| A8 | 機器シミュレータは同梱の別バイナリ `envmon-sim` とし、結合テストと手動デモに使う |
| A9 | 対応 OS は Windows 10 / 11 Pro、Windows Server 2019 / 2022 (x64) |
| A10 | アニメーション GIF は先頭フレームを下絵として使う |

## 5. 決定事項 (2026-11-17 PO 承認)

| # | 項目 | 決定 |
|---|------|------|
| Q1 | フェーズ分け | §4 のとおり |
| Q2 | 暗号方式 | TLS 1.3 + 相互認証 (アプリと機器の双方を自前 CA の証明書で認証)。AES-256-GCM 電文暗号は TLS を使えない実機アダプタでのみ使う |
| Q3 | 確認操作後の扱い (AL-1) | 確認で警告音と赤点滅を止め、ドアが開のままならアイコンは「開 (確認済)」で表示。閉に戻ったら通常表示に戻る |
| Q4 | 組込みスクリプト | **Lua** (PO 指定) |
| Q5 | WebAPI 方式 | REST (HTTPS)。gRPC は採用しない |
| Q6 | ライセンス | 構成ファイルによるオプション有効化のみとし、ライセンスキー認証は実装しない |
| Q7 | スケジュールの粒度 (AC-1) | 曜日ごとの時間帯 + 有効期間。祝日カレンダーは後で追加 |
| Q8 | アンチパスバック | ゲートコントローラ構成時だけでなく、PC 側の照合でも有効にできるようにする (P4) |
| - | 下絵形式 | **GIF / JPEG** (PO 指定。spec.md §4.2 を変更) |
| - | 操作方法 | **下絵上のオブジェクトで操作する** (PO 指定。UI-5) |
